## Decision Log

Решение: использовать один положительный радиус для обеих дуг по прямому указанию пользователя; предлагаемый начальный ввод 5 мм. Это новый радиус, не преобразование прежнего осевого смещения 5 мм. Дата: 2026-10-13.

Решение: плоскость задаётся касательной TCP при обработке и осью отверстия. Начальное направление подвода — внутрь вдоль оси, конечное — по обработке; отвод начинается по обработке и заканчивается наружу вдоль оси. Это предложенная геометрия из обсуждения, которую реализует данный план после разрешения пользователя.

Решение: сохранить разгон/торможение в процентах длины, фиксированные LIN и остановки между LIN и дугами. Не подменять их новым законом ориентации.

Решение: по последующему указанию пользователя вернуть предложенную кубическую интерполяцию ABC по доле длины с согласованием первых производных на границах обработки; затем преобразовывать ABC в матрицу для IK. На свободных концах производные ABC по длине нулевые. Ветви углов предварительно согласовать, вырождение представления Euler обрабатывать явно, не скрывать переходом на иной закон.

Решение для первого эксперимента: число точек анимации вычислять по геометрии и времени один раз. Проверку ошибки TCP, возникающей из интерполяции углов между точками, пока исключить, как и вызванное ею дробление интервалов. IK, конечность, пределы углов и проверки скоростей на назначенных точках сохраняются; их провал выдаёт ошибку, не увеличивает число точек. Это не разрешение отключить проверки RSI. Dry Run только воспроизводит заранее подготовленные углы, без расчёта новых TCP-поз и IK. Геометрический допуск не объявлять гарантией точности TCP после интерполяции углов. Дата: 2026-10-13.

### Шаг 2. Геометрия окружностей

Получить точку TCP и производную его положения в начале/конце обработки из той же аналитической геометрии, что используется evaluate. Выделить общий расчёт положения и производных, возвращающий значение; не вычислять касательную по хорде между точками анимации. Учесть flipAxis и направление обхода.

Все векторы ниже выражены в BASE. Для каждой границы отдельно: \(\bar p_b\) — положение TCP в мм; \(\bar e_x\) — нормированная производная положения по направлению обработки; \(\bar e_z^H\) — наружная ось отверстия. Величины фиксированы для построенной дуги. Определить безразмерный скаляр \(c=\bar e_x\cdot\bar e_z^H\) и орт \(\bar e_y=(\bar e_z^H-c\bar e_x)/\sqrt{1-c^2}\). При вырожденной касательной или почти параллельных направлениях вернуть ошибку через result, без произвольной запасной плоскости. Допуск обосновать точностью существующих геометрических проверок и записать при реализации.

При радиусе R в мм центр окружности \(\bar o=\bar p_b+R\bar e_y\). Угол подвода \(\beta_L=\arccos(-c)\), угол отвода \(\beta_O=\arccos(c)\), оба в радианах. Для каждого участка его длина \(L=R\beta\). Независимый параметр u — доля длины своего участка, от 0 до 1.

Положение подвода:

\(\bar p_L(u;\bar p_b,\bar e_x,\bar e_y,R,\beta_L)=\bar p_b-R\sin[\beta_L(1-u)]\bar e_x+R\{1-\cos[\beta_L(1-u)]\}\bar e_y.\)

Положение отвода:

\(\bar p_O(u;\bar p_b,\bar e_x,\bar e_y,R,\beta_O)=\bar p_b+R\sin(\beta_Ou)\bar e_x+R[1-\cos(\beta_Ou)]\bar e_y.\)

Не получать отвод обращением времени подвода: это даёт неверное направление на стыке с обработкой. При u=1 подвода и u=0 отвода возвращать исходную граничную точку без накопления тригонометрической погрешности. Норма первой производной по u равна L, производная этой нормы равна нулю; phaseArcDifferential для дуг возвращает эти точные величины. Метаданные edgePoint/radialNormal для дуги должны явно относиться к фиксированной границе обработки; проверить их потребителей и не выдавать их за пересчитанную точку контакта на каждом участке подвода.

### Шаг 3. Ориентация и вход IK

Начальную ориентацию подвода задавать как в существующем положении вне обработки: орт Y TCP противоположен наружной оси отверстия, орт Z TCP направлен радиально наружу в фиксированной точке начала обработки, орт X равен векторному произведению Y на Z. Конечную ориентацию взять без изменений из evaluate на границе обработки. Для отвода порядок противоположный.

При подготовке точек вычислять кубические ABC, затем полную ортонормальную матрицу, её столбцы являются ортами TCP. Положение и матрица составляют TCP-позу; существующее преобразование к фланцу и IK дают шесть углов сочленений. ABC не являются входом этого IK. Во время Dry Run этот расчёт не повторяется.

Сравнить односторонние скорости вращения TCP на стыках с обработкой. Совпадение конечных матриц не означает совпадения скоростей вращения. Простой поворот между двумя фиксированными ориентациями не гарантирует этого совпадения. Не отключать проверки ради успешной генерации; если выбранный простой закон даёт скачок, описать величину и согласовать закон с производной ориентации обработки до объявления готовности. Изменение геометрии окружности само по себе этого не исправляет.

### Шаг 4. Длина и время

Сохранить ChamferArcLength и quintic inverse для обработки. Добавить внутри этого существующего типа точный режим постоянного отношения длины и параметра для круговых фаз: длина L=R*beta, progressAtDistance(s)=s/L, distanceAt(u)=L*u. s — пройденная длина в мм, u — безразмерная доля длины. Режим не должен запускать интегратор, создавать аппроксимационные полиномы или выполнять поиск при запросе. Публичный контракт и проверки диапазона сохранить. Это позволяет сохранить массив трёх отображений в ChamferCentralMotion без отдельных алгоритмов в анимации и RSI.

Обозначим f — долю разгона/торможения от 0 до 1, V — скорость обработки в мм/с. Для каждой дуги существующий профиль использует расстояние разгона/торможения f*L, ускорение V²/(2*f*L), время разгона/торможения 2*f*L/V. Подвод: разгон от нуля, затем V. Отвод: V, затем торможение до нуля. При f=1 участка постоянной скорости нет. При общем радиусе разные углы могут давать разные длины и, при одинаковом f, разные ускорения. По локальному времени существующие leadInState/leadOutState дают s, затем u=s/L и новая evaluatePhase дают полную позу.

### Шаг 5а. Заранее назначенное число точек анимации

Для каждой части с постоянным касательным ускорением вычислить N=max(1,ceil(T*sqrt(Amax/(8*epsilon)))). N — число интервалов, T — длительность части в секундах, epsilon — выбранный допуск положения 0.01 мм, Amax — верхняя граница полного ускорения TCP в мм/с². Затем назначить N+1 точек с шагом T/N, общие концы хранить один раз. Для окружности Amax=sqrt(a_tau²+Vmax⁴/R²): a_tau — модуль касательного ускорения в мм/с², Vmax — максимальная скорость части в мм/с, R — общий радиус в мм. Границы разгона/постоянной скорости/торможения включать точно.

Для обработки Amax=V²*K, где V — постоянная скорость, K — аналитическая верхняя граница кривизны реальной траектории TCP, мм⁻¹. Нельзя автоматически брать кривизну исходной кромки a/b²: текущий evaluate добавляет смещение фаски. Получить консервативную границу через производные той же формулы, без поиска максимума по пробным точкам. При выводе через азимут вокруг оси цилиндра нижняя граница нормы первой производной для неотрицательной фаски — радиус отверстия; границу второй производной вывести и записать перед реализацией. Не использовать неподтверждённую оценку как готовую гарантию.

В назначенных точках один раз получить аналитическую TCP-позу, решить IK последовательно и сохранить углы/времена. Не запускать прежнюю сетку 4 мс с четвертями, не добавлять точки для проверки интерполяции углов. Несовместимость выбранной конфигурации сообщать ошибкой. Сохранить нынешнее воспроизведение линейной интерполяцией углов и FK. Формула определяет лишь геометрический критерий выбора исходной сетки; фактическую ошибку такого воспроизведения пользователь согласился пока не проверять. Никаких гарантий 0.01 мм после интерполяции углов не заявлять.

## Шаг 5а — реализованный расчёт и обоснование

Для окружностей используется Amax=hypot(a,V²/R). Здесь Amax — верхняя граница полного ускорения начала TCP, мм/с²; a — модуль постоянного касательного ускорения на рассматриваемой части, мм/с² (ноль на части постоянной скорости); V — максимальная скорость этой части, мм/с; R — радиус дуги, мм. В каждом участке разгона/торможения V равна скорости обработки. Границы частей берутся из ChamferCentralMotion::profile и phaseTimes, включая случай 100%, при котором отдельная часть постоянной скорости отсутствует.

Для обработки получена следующая консервативная оценка по той же геометрии, что и ChamferPath::evaluate. Фиксированные параметры: ρ — радиус цилиндра (minorRadius), мм; c — размер фаски, мм; γ — угол фаски, радианы; H — тангенс угла наклона плоскости к поперечному сечению цилиндра, безразмерный; b=cot(γ). Азимут α вокруг цилиндра — независимый параметр, радианы, не параметр исходного эллипса. Векторы выражены в BASE: наружная ось — орт \bar{e}_z, центр эллипса — \bar{o}, единичное радиальное направление — \bar{r}(α). В обозначениях ниже фиксированная геометрия перечислена после точки с запятой.

Пусть h(α;H,δ)=H*cos(α-δ) — наклон плоскости в радиальном направлении, δ — фиксированный азимут максимального наклона, радианы. Тогда |h|, |dh/dα|, |d²h/dα²| не больше H. Обозначим g(h)=1/sqrt(1+h²). Для g(h(α;H,δ)) модуль первой производной по α не больше H, второй — не больше D=2H²+H, поскольку |dg/dh|<=1 и |d²g/dh²|<=2.

Положение TCP, полученное раскрытием faceDirection и depthRatio из evaluate:

\bar{p}(α;\bar{o},ρ,c,γ,H,δ,\bar{e}_z)=\bar{o}+ρ*[\bar{r}(α)+h(α;H,δ)*\bar{e}_z]+(c/2)*g(h(α;H,δ))*[\bar{r}(α)+(2h(α;H,δ)-cot(γ))*\bar{e}_z].

Радиальная компонента второй производной добавки фаски ограничена B_r=D+2H+1, осевая — B_z=2H+4H²+(2H+b)D. Следовательно M=ρ*sqrt(1+H²)+(c/2)*(B_r+B_z) ограничивает норму второй производной положения по α в мм. Компонента первой производной вдоль производной радиального орта равна ρ+(c/2)*g, не меньше ρ при c>=0. Поэтому K=M/ρ² — верхняя граница кривизны, мм⁻¹, а Amax=V²*K. Эти выражения дают одну оценку без пробных точек и поиска максимума. Они относятся к аналитической модели пересечения цилиндра с плоскостью; существующий допуск согласования входного эллипса и численная погрешность обращения длины не превращаются в строгую машинную гарантию.

Для каждой части заранее назначается N=max(1,ceil(T*sqrt(Amax/(8ε)))), ε=0.01 мм; T — длительность части, с. Это следует из оценки отклонения кривой от линейной интерполяции положения по времени Amax*(T/N)²/8. Сохраняются N+1 временных точек с общими концами один раз. Условный числовой пример: R=5 мм, дуга π/2, V=1 мм/с, разгон на 100% длины. Длина 7.8539816 мм, T=15.7079633 с, a=0.0636620 мм/с², Amax≈0.209888 мм/с²; N=26, то есть 27 поз на дуге до объединения общих концов. Это расчёт по формуле, не запуск приложения и не измерение времени подготовки.
