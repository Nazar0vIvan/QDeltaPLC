# RSI_Hole minimal nominal experiment

The current experiment is HOME -> Ps -> clear lead-in start -> nominal
RSI lead-in/machining/lead-out -> Ps -> HOME. Force correction is disabled.
The controller source is `RSI_Hole.src` / `RSI_Hole.dat`; the Ethernet
configuration is `RSI_Hole_EthernetConfig.xml`; the signal connections are
in `RSI_Hole_DIAGRAM.md`. This replaces the earlier extended graph contract.

## Ethernet signals

ETHERNET1 has two signal inputs and eight signal outputs. Its ConfigFile is
`RSI_Hole_EthernetConfig.xml`. The existing PC address/port and ImFree type
are preserved. RIst is read internally and consumes no signal input.

| Direction | Port | XML field | Connection |
| --- | --- | --- | --- |
| Controller -> PC | In1 | Start, BOOL | SEN_PINT reads $SEN_PINT[1] |
| Controller -> PC | In2 | Result, LONG | SEN_PINT reads $SEN_PINT[2] |
| PC -> controller | Out1..6 | RKorr.X/Y/Z/A/B/C, DOUBLE | POSCORR1 CorrX/Y/Z/A/B/C |
| PC -> controller | Out7 | Stop, BOOL | STOP1 In1 |
| PC -> controller | Out8 | Result, LONG | MAP2SEN_PINT writes $SEN_PINT[2] |

POSCORR1 uses RefCorrSys=Base. STOP1 uses Mode=ExitMoveCorr and Channel=0.
KRL selects relative IPO_FAST processing, with one correction per 4 ms cycle.
XYZABC outputs use HOLDON=0; Stop and Result use HOLDON=1. The graph contains
no Job/Sample exchange, STATUS/AND gate, CorrectionStatus field, GREATER or
second STOP branch. Existing numerical correction-limit checks and POSCORR
parameters are separate from this simplification; no controller limits are
changed by these source artifacts.

## Start and finish

KRL owns $SEN_PINT[1]. Its existing assignments clear it before the experiment,
set it immediately before RSI_MOVECORR, and clear it after that call returns.
Start reports this request directly; it is not a verified MOVECORR-active status.
There is no additional active-motion detector in this minimal graph.

KRL clears $SEN_PINT[2] before RSI_ON. The graph then writes the PC's Result:
0 while running or stopping unsuccessfully, and 1 for normal completion.
The existing Completed=($SEN_PINT[2]==1) check alone permits the return motions.

The PC replies with zero corrections while Start=0. During the nominal run it
supplies the prepared XYZABC increments with Result=0 and Stop=0. After the
last correction it sends zeros with Result=1 and Stop=0, waits for the Result=1
echo, then raises Stop with zeros and Result=1. An unsuccessful stop keeps
Result=0 and raises Stop. There is no recovery or return-to-trajectory sequence.
IPOC is generated by the controller and copied unchanged into each PC reply.

Example controller request:

```xml
<Rob TYPE="KUKA">
  <RIst X="0" Y="0" Z="0" A="0" B="0" C="0" />
  <Start>1</Start>
  <Result>0</Result>
  <IPOC>123456</IPOC>
</Rob>
```

Example running/hold reply:

```xml
<Sen Type="ImFree">
  <RKorr X="0" Y="0" Z="0" A="0" B="0" C="0" />
  <Stop>0</Stop>
  <Result>0</Result>
  <IPOC>123456</IPOC>
</Sen>
```

## Existing integration and implementation boundary

KRL uses the existing /RoboCrapJobs mount and opens
/RoboCrapJobs/shared_data.txt (PC C:\RoboCrapJobs\shared_data.txt).
The file has exactly five numeric rows, no header, keys or mapping:

1. Ps as X;Y;Z;A;B;C.
2. Clear lead-in start as X;Y;Z;A;B;C.
3. Clear lead-out end as X;Y;Z;A;B;C.
4. Transfer velocity for $VEL.CP, in m/s.
5. Transfer acceleration for $ACC.CP, in m/s squared.

XYZ are TCP coordinates in mm relative to BASE; ABC are Z-Y-X Euler angles
in degrees. Decimal points use the C locale; rows end with CRLF. The existing
READ_FRAME(FileHandle, Ok) reads each frame with "%f;%f;%f;%f;%f;%f" and reports
#DATA_OK through Ok. Two krl_fscanf calls with "%f" read the scalars. The
existing CLOSE_FILES() helper closes remaining handles. These user-supplied
helpers must already be available on the controller; they are not redefined.
Read/close failures or nonpositive rates terminate before PTP Ps. Rates above
$VEL_MA.CP or $ACC_MA.CP also terminate. KRL sets $VEL.CP and $ACC.CP immediately
before each LIN. It retains $ADVANCE=0 and unapproximated moves. The actual KRL
profile remains controller-generated, subject to machine data and overrides;
the Dry Run trapezoid is not a controller interpolation guarantee.

PsOut retains Ps XYZ and LeadEnd ABC. TOOL_DATA[6], LOAD_DATA[6] and BASE_DATA[1]
are selected after HOME. These installed frames must correspond to the saved
application calibration. Initial HOME still occurs before the file read.

RSI Sampling builds the payload on its copied-input numerical worker and writes
it only after accepting the current result. QSaveFile atomically replaces the
file, with direct-write fallback disabled. Missing C:/RoboCrapJobs is created.
The export requires encodingReady, including the configured correction-limit
checks. Failure preserves the sampled job and reports a separate export status.
Stale workers never publish. Clearing the prepared job clears export status but
does not delete the previous file; the five-row format contains no identity or
freshness token. A previous file must not be mistaken for the current job after
failed sampling/export or invalidation.

The first two rows share encoding.initialCoordinates ABC. The third row uses
initialCoordinates plus cumulative serialized RSI increments, preserving the
terminal Euler branch. Staging/end frames are checked against saved poses.
Transfer settings come from the immutable motion snapshot and are divided by
1000 to convert mm-based units. The nominal correction stream is not stored in
this file. Decimal serialization does not remove controller REAL rounding or
guarantee that actual RIst ABC retains the requested branch; the future session
must validate the controller's actual initial pose and branch before execution.

Prepared nominal samples, serialized XYZABC increments and their offline audit
remain available. The existing RsiHoleProtocol C++ serializer/decoder still uses
the earlier extended State schema and is not compatible with this minimal XML.
It is not connected to nominal device execution; aligning PC wire processing
and running the nominal session are the next integration work. The active RSI
demonstration is unchanged and is not a peer for this experiment.
