# Правила оформления технических документов

Проект редакции. Цель — сокращать изложение, сохраняя содержание и каждое математическое преобразование.

## 0. Порядок применения

### 0.1. Задача и границы

Запрос задаёт режим:

- вопрос или проверка — ответ и найденные нарушения; сами по себе они не поручают правку;
- оформление — правка записи и текста с сохранением способа вывода, результатов и всех корректных шагов;
- содержательная переработка — разрешённая смена содержания или способа вывода в заданных границах.

Явное поручение изменить файл не требует повторного разрешения. Меняй указанный фрагмент; вне него — только разрешённые зависимости. При обычном оформлении это номера формул и ссылки, затронутые перенумерацией. Прочие внешние проблемы собирай для отчёта.

При конфликте сначала сохраняй математическую корректность, факты, условия и ограничения, затем подробность и оформление, затем сокращай текст. Прямое указание автора задаёт режим текущей задачи.

Если аудитория не задана, предполагается инженер, знакомый с линейной алгеброй и математическим анализом. Общие знания этой аудитории не повторяй.

### 0.2. Контекст документа

Граница правки не ограничивает чтение. Определения, обозначения, допущения, данные и основания действуют во всём документе, кроме явно заданных локальных областей. Подраздел наследует область раздела до её явного изменения.

Перед работой:

1. Прочитай целевой документ полностью; при ограничении вывода — последовательными порциями без пропусков. Обзор структуры и поиск не заменяют чтение.
2. Найди определения и основания используемых терминов, символов, условий и результатов. Проверь ссылки из фрагмента и на него.
3. Собери назначения обозначений во всём документе: полные записи, варианты LaTeX и словесные названия.
4. Зафиксируй сохраняемые факты, условия, значения и математические шаги; при оформлении — все корректные шаги исходного вывода.

При переходе к другому подразделу используй уже найденные сведения. Отсутствующие сведения и недоступные части назови вместе с зависимыми от них проверками. Не выдумывай определения, числа, пороги, источники и условия; при пробеле не объявляй проверку полной.

Служебные перечни определений, оснований и проверок включай только в запрошенный отчёт.

### 0.3. Правка и проверка

Порядок: контекст и структура → математическая корректность и полнота шагов → обозначения → формулы и таблицы → язык и сокращение → зависимости. После правки сопоставь сохраняемые сведения и преобразования с исходными; повтори проверку свойств, затронутых последующими изменениями. Итоговая проверка — раздел 7.

Статусы: **пройдено**, **нарушение**, **неприменимо**, **недостаточно данных**. Для нарушения укажи место и правило; для неприменимости — причину; для недостатка данных — пробел и зависимый вывод.

### 0.4. Механические проверки

Команды для Git Bash; `F` — путь к Markdown-файлу. Совпадения — кандидаты в нарушения, требующие разбора. Отсутствие совпадений не подтверждает корректность.

```bash
F=docs/calibration/ROBOT_PROBE_SPHERE_CALIBRATION_THEORY_RU.md
# 1. Unicode-математика вне распознанных формул и строчного кода
perl -CSD -ne '$m=!$m if /^\$\$\s*$/; next if $m || /^\$\$/ || /^!\[/; s/`[^`]*`//g; s/\$[^\$]*\$//g; print "$.: $_" if /[\x{3B1}-\x{3C9}\x{391}-\x{3A9}\x{304}\x{1D62}\x{2096}\x{2080}-\x{2089}\x{1D40}\x{207B}\x{2265}\x{2264}\x{2260}\x{2248}\x{B7}\x{D7}\x{221A}\x{2208}\x{2202}\x{27E8}\x{27E9}\x{2016}\x{226A}]/' "$F"
# 2. Номер формулы без ссылки ниже; ссылка на несуществующий номер
perl -CSD -ne 'push @L,$_; END{ for $i (0..$#L){ $T{$1}=$i while $L[$i]=~/\x5ctag\{([0-9.]+)\}/g } for $i (0..$#L){ next if $L[$i]=~/\x5ctag\{/; while($L[$i]=~/\((\d+(?:\.\d+)+)\)/g){ $c=$1; if(exists $T{$c}){ $later{$c}=1 if $i>$T{$c} } else { print "line ",$i+1,": ($c) has no tag\n" } } } for $t (sort keys %T){ print "($t) at line ",$T{$t}+1,": no citation below\n" unless $later{$t} } }' "$F"
# 3. Возможные неясные ссылки и повторы
grep -nE 'формул[аеуыи]* (выше|ниже)|\((выше|ниже)\)|цепочк[аеуи] выше|шаг[аеу]? [0-9]+ раздела|итог[аеу]? шага|обеих сумм|последн(ее|ем) слагаем|средн(ее|ем) слагаем|равенств[а-я]* —|переход[а-я]* —|то есть|иначе говоря|Под корнем' "$F"
# 4. Перенос формулы без «=» в конце строки и в начале следующей
perl -CSD -ne '$d+=()=/\x5cbegin\{[bpv]?matrix\}/g; $d-=()=/\x5cend\{[bpv]?matrix\}/g; if($pe && $_!~/^\s*\x5cend/ && ($pb!~/=\s*\x5c\x5c\s*$/ || $_!~/^\s*=/)){print "$.: $_"} $pe = (/\x5c\x5c\s*$/ && !/&/ && $d==0); $pb=$_' "$F"
# 5. Оценочные слова, для которых может требоваться критерий
grep -nE '(^|[^А-Яа-яё])(мал(ая|ое|ые|ый|ой|ую|а|о|ы)?|допустим[а-я]*|достаточн[а-я]*|существенн[а-я]*|незначительн[а-я]*|небольш[а-я]*|примерно)([^А-Яа-яё]|$)' "$F"
```

Команды распознают не все варианты Markdown и LaTeX. При смене среды исполнения проверь сохранность экранирования регулярных выражений.

## 1. Структура и форма подачи

1. Заголовок называет предмет или получаемый результат. «Анализ» без предмета заменяется на конкретное название.
2. Содержание раздела должно отвечать заголовку. Отдельную тему выделяй, если она содержит запрошенный результат, определяет используемое понятие, обосновывает решение или конкретный переход либо задаёт исходные данные; иначе не добавляй её.
3. Каждый раздел и подраздел начинай с краткого описания цели, включая определения, таблицы и краткие замечания. Цель не пропускай из-за заголовка. Раздел с выводом заканчивай искомым результатом.
4. Выбирай форму по типу сведений: соотношение — формула; сравнение однотипных объектов — таблица; последовательность или условия — перечень; пространственная связь — рисунок. В причинном тексте назови обосновываемый выбор метода, действие, ограничение или вывод и основание по П5.
5. Не пересказывай словами то, что уже однозначно записано формулой. Сохраняй условия, основание преобразования и пояснения, без которых запись допускает другое толкование. Рисунок словами не объясняй: подпись называет, что изображено; словесное описание рисунка пишется только по требованию автора.
6. В доказательстве порядок такой: поставленная задача → доказательство → установленный результат. Формулировка доказываемого положения не является утверждением, что оно уже доказано.
7. Порядок изложения определяется зависимостями понятий и результатов. Независимые способы и ограничения могут излагаться параллельно.

Неоднозначность, обоснованность и избыточность проверяются по разделу 9.

## 2. Математические выкладки

1. Показывай каждое преобразование отдельно: подстановку, раскрытие скобок, группировку, сокращение, транспонирование и перестановку. Не объединяй несколько преобразований ради уменьшения объёма.
2. Подстановку вводи ссылкой: «Подставим (5.2.11) в …». Сначала подставь выражение без преобразований; следующие преобразования запиши отдельными шагами.
3. Каждый переход следует из предыдущей строки, указанного определения, ранее полученного соотношения или явно названного основания. Ссылка на определение допустима только для перехода, который из него следует.
4. При содержательной переработке выбирай способ с меньшим числом шагов, сохраняя объекты, допущения, области и кванторы задачи, точность и локальность утверждения. При оформлении способ не меняй.
5. Производные записывай через частные производные; приращения не подменяют производные.
6. Для нового математического объекта задай общий вид перед частным случаем. Если общий вид уже введён, используй его или ссылку на него.
7. Доказательство свойства величины начинай с выражения этой величины. Например, вывод о сумме квадратов невязок начинается с суммы квадратов невязок.
8. Математические условия записывай предикатами с нужными кванторами. Общие области, размеры и ориентации объектов из 4.10 наследуются частными выражениями.
9. Различай необходимое и достаточное условие, равенство и приближение, локальное и глобальное утверждение. У приближения сохраняй условия применимости.
10. Соблюдай буквальный смысл: координаты центра являются элементами вектора, а не самим центром.
11. Название теоремы или метода используй после проверки по источнику. Если название не установлено, сформулируй результат без названия.
12. Поясняющий пример включай для названной трудности: выбора между двумя прочтениями, применения нового определения или границы применимости. Укажи, что он различает или поясняет; сопоставь упрощённые обозначения с основными. Размещай пример до поясняемого результата.

## 3. Формулы

1. Самостоятельное соотношение и каждый блок вывода записывай в `$$…$$`. Обозначения и короткие выражения внутри предложения — в `$…$`.
2. Строки многострочного вывода центрируй с `gathered`. Переноси цепочку равенств по «=»: знак в конце строки повторяется в начале следующей. Не разрывай один шаг. Короткие равенства оставляй вместе, если их размещение в среде вывода проверено; иначе каждый шаг — отдельной строкой.
3. Первая формула и непосредственно следующий блок «где …» считаются одним введением. Частный случай заданного семейства обозначений новым символом не считается.
4. В «где …» включай новые обозначения из формулы; состав определения — 4.10. Первое определение — на строке со словом «где», следующие — с новой строки; разделитель «;», последнее определение заканчивается точкой.

   Для Markdown проекта:

   ```text
   где $G$ — матрица размером $6 \times 6$;
   &emsp;&emsp;$\bar{b}$ — вектор-столбец размером $6 \times 1$, мм.
   ```

   Между определениями нет пустых строк. Если новых символов нет, блока «где …» нет. Необходимое пояснение записывается отдельным абзацем.

5. Последний шаг вывода записывай как остальные шаги. Важный результат приводи после вывода отдельным блоком «начало вывода = конец вывода» в `\boxed{…}`; `\tag` ставь на этот блок. Такой блок не считается повторной записью формулы по 3.11.
6. Указывай все аргументы функций, включая зависимые аргументы.
7. Векторы и блочные строки записывай через `bmatrix`; столбец допускается как транспонированная строка. Отрицательный соседний блок отделяй, например: `\begin{bmatrix} A \quad & \quad -I \end{bmatrix}`; минус относится ко второму блоку.
8. Числовые координаты в тексте и таблицах записывай в круглых скобках. При десятичной запятой разделяй координаты точкой с запятой.
9. Нумеруй формулы, на которые есть ссылка ниже. Номер состоит из номера подраздела и порядкового номера формулы: например, (5.3.1); в Markdown — `\tag{5.3.1}`.
10. Формулу внешнего источника обозначай отдельно от внутренних ссылок: «L7, формула 3.2». Внутренняя ссылка имеет вид «из (5.3.1)».
11. Вместо повторной записи формулы используй её номер. Самостоятельные шаги преобразования и подстановки из раздела 2 не считаются лишним повторением. Указатели «формула выше/ниже» заменяй номером.

Это настройки оформления проекта. Ссылку на ГОСТ добавляй только с проверенными обозначением, редакцией и пунктом стандарта.

## 4. Обозначения

1. Для вектора используй строчную букву с чертой: $\bar{r}$. Систему координат указывай левым верхним индексом, точки — нижними индексами от начала к концу вектора.
2. Букву l для векторов не используй. Орт обозначай e с чертой и индексом оси или направления: $\bar{e}_x$. Буква e в математических обозначениях проекта зарезервирована для ортов.
3. Один и тот же вектор в разных системах сохраняет базовую букву; меняется индекс системы. Для нормированного направления используй соответствующий орт.
4. Полная запись (буква, начертание, индексы) имеет один смысл в своей области. Новое назначение сверяй с записями и семействами из 0.2.3. Общая буква допустима при разных однозначных полных записях. Коллизия в данной области — одна полная запись для двух объектов либо два смысла используемого сокращения; сначала восстанови индексы или имя, затем при оставшейся неоднозначности выбери другую букву.
5. Сохраняй принятые в документе назначения. В частности, $v$ — скорость, $A$ — угол ориентации KUKA, когда рассматриваются именно эти величины.
6. Для расстояния используй L; d сохраняй для диаметра. Матрицу преобразования из i в j обозначай ${}^{j}A_i$ и называй матрицей преобразования.
7. Составные индексы разделяй точкой: $p_{a.det}$.
8. Называй предмет кратко: «вектор параметров, найденный МНК». Не расшифровывай точки и систему координат из индексов. Если есть значения из разных опытов, касаний, режимов или наборов данных, сохраняй различающий их признак, ещё не заданный индексом или контекстом.
9. Обозначение — символ объекта или величины: $\alpha$, $r$, ${}^{B}\bar{e}_x$.
10. При введении обозначения укажи символ и название; словесный смысл — если он не задан определяющей формулой. Добавь применимые сведения: единицы, область значений, размер матрицы или вектора, ориентацию вектора, диапазон и смысл индексов, способ получения величины. Эти сведения далее наследуются.
11. Вычисляемую величину вводи формулой с предметным названием: $d$ — диаметр, $d = 2r$.
12. Единицы величин записывай обозначениями единиц (°, мм, мм/с), а не словами («градусы», «миллиметры»).
13. Обозначение вводи при первом употреблении: фразой «Пусть $\alpha$ — угол между осью инструмента и нормалью к поверхности, °», перечнем непосредственно перед использованием либо блоком «где …» по 3.3. Перечни для последующих разделов не составляй. Исключение — раздел 2.1 «Системы координат» [теории калибровки щупа](../RoboCrap/docs/calibration/ROBOT_PROBE_SPHERE_CALIBRATION_THEORY_RU.md).

Доступность смысла и выбор короткой записи — П7.

## 5. Таблицы и профиль отображения

Выбирай профиль по среде результата. Таблица задаёт настройки проекта. Для иной среды различай настройки автора, подтверждённые сведения о возможностях и фактический просмотр; неизвестные свойства отображения отметь как непроверенные.

| Элемент | Markdown для MarkText | Ответ в чате |
| --- | --- | --- |
| Обозначение или выражение в тексте | Строчная формула `$…$` | Строчная формула `$…$` |
| Самостоятельная формула | Блок `$$…$$` | Блок `$$…$$` |
| Левый верхний индекс | Допускается строчно | Отдельный блок |
| Ячейки таблиц | Допускаются строчные формулы | Слова, числа и читаемые Unicode-обозначения без LaTeX |
| Отступ строк «где …» | `&emsp;&emsp;` | Без HTML-отступов |

В Markdown не подменяй LaTeX Unicode-математикой. Исключения: названия осей, запись ориентации из программы робота, программные идентификаторы и числовые векторы из таблиц данных.

В формуле внутри ячейки используй `\lvert … \rvert` вместо вертикальной черты — разделителя ячеек. Десятичную запятую в LaTeX записывай как `{,}`.

MarkText разрывает слово внутри, если столбец таблицы узкий. Поэтому каждое слово заголовка таблицы и каждое слово короткой ячейки-названия — поля карточки, категории, обозначения — заключай в отдельный `<nobr>…</nobr>`: `| <nobr>ограничения</nobr> |`, `| <nobr>Вид</nobr> <nobr>записи</nobr> |`. Несколько слов в один `<nobr>` не заключай: такая ячейка не переносится по пробелам.

Заголовок таблицы, столбца или предшествующее определение должны объяснять величину, единицы и категории. Общие сведения указываются один раз. Каждую ячейку проверь на соответствие заголовку, происхождение данных по П8 и синтаксис выбранного профиля.

## 6. Терминология и язык

1. Применяй термины русской инженерной и математической литературы в предметном значении. В проекте используй «МНК-оценивание», «невязка», «идентифицируемость», «сочленение». Не объединяй разные понятия ради единообразия: «приращение» и «поправка» выбираются по смыслу. Спорное значение сверяй с доступным профильным источником; без доступа отметь его непроверенным. Для каждого базового слова повторный поиск не требуется.
2. Называй объект свойства: «перебег шарика». Выбор записи с названием или символом — П7б.
3. Используй буквальное описание вместо метафор и олицетворений. Проверяй грамматику, падежи, тавтологии и случайное изменение смысла термина.
4. Действующий объект или носитель свойства должен быть ясен там, где возможны разные толкования. Допускаются краткие математические конструкции «подставим», «получаем», «отсюда следует» без отдельно выписанного подлежащего.
5. Термин — слово или словосочетание, называющее понятие. Определяй используемый новый смысл проекта или понятие вне знаний аудитории 0.1, независимо от числа употреблений. Вычислимость величины не отменяет её названия. Условное короткое имя регулируется отдельно 6.7.
6. Объясняй новый смысл через известные. Не определяй его тем же нераскрытым словом или кругом отсылок. Общий корень сам по себе не образует круга: родовая часть «матрица поворота — матрица…» допустима.
7. Условное название — короткое имя вместо повторяющегося описания. Вводи его или сокращение, только если без него описание понадобилось бы не меньше трёх раз. После правки проверь не меньше трёх употреблений вне определения; иначе раскрой имя. Не дописывай употребления ради порога.
8. Фактор влияния не упоминай только номером (ФВ7) — ни в документе, ни в ответе в чате: либо опусти номер, либо пиши его с названием фактора, например «ФВ7 (повторяемость робота)».
9. Формулируй утверждение прямо. Двойное отрицание заменяй положительной формой того же смысла.

Неясные ссылки проверяй по П3, избыточность — по П10.

Неразобранный кандидат или недоступные необходимые сведения не допускают статуса полной проверки. При отсутствии нарушений правки не требуются.

## 8. Ответы в чате

1. Дай запрошенный результат и нужные для него основания. Удали повтор постановки и сведения, не объясняющие результат. Объём и состав ответа определяются задачей: вопрос допускает краткий ответ, исследование требует обоснования.

5. Не добавляй шаблонный раздел «что дальше». Необходимые предложения формулируй обычным текстом.

## 9. Проверяемые правила изложения

Для всех правил действует контекст из подраздела 0.2.

### П1. Назови объект и характеристику

Если «ошибка», «размер», «значение», «разброс» и подобное название допускает несколько характеристик, укажи нужную: например, модуль вектора, норму матрицы с её видом, СКО невязок. Определение или заголовок таблицы засчитывается.

Проверка: можно однозначно установить объект и характеристику. При сравнении совпадают их смысл, единицы и применимые условия либо указан переход между ними.

### П2. Задай критерий условия и оценки

**П2а.** Условие задаётся математическим предикатом, состоянием, событием, категорией с определёнными признаками или ссылкой на такое условие. Проверка: описан способ установить его выполнение; не требуется, чтобы любая теоретическая предпосылка непосредственно измерялась.

**П2б.** Если «мал», «достаточен», «допустим» или другое оценочное слово определяет вывод или действие, укажи критерий и его происхождение. Для количественного решения укажи порог. Проверка: решение не зависит от неоговорённой оценки читателя.

Если критерий отсутствует, назови пробел; не придумывай его. Цитируемую оценку без критерия обозначь как оценку источника и не используй как установленный критерий.

### П3. Устрани неоднозначную ссылку

Местоимение или указатель допускается, если в текущем или непосредственно предыдущем предложении есть единственный подходящий объект, действие или результат. При двух возможных толкованиях назови нужный предмет. Для более далёкой ссылки используй короткое название, обозначение или номер.

Проверка: для ссылки установлено одно толкование. «Датчик соединён с контроллером. Он перезапускается» требует названия устройства; однозначное «он» не требует замены.

### П4. Покажи необходимую логическую зависимость

Если шаг использует ранний результат, укажи его и отношение: подстановка, следствие, проверка, ограничение или противопоставление. Пронумерованный результат указывай номером.

Проверка: указанный результат и вид отношения обосновывают именно этот переход. Независимые сведения не требуют причинной связки или повторения предыдущего абзаца.

### П5. Обоснуй техническое утверждение

**П5а.** Для технического утверждения, на котором основан результат документа, найди вывод, источник, измерение, расчёт или заданное условие. Источник указывается с местом; расчёт — с методом и исходными данными; измерение — со ссылкой на запись и методику. Общее основание допускается для явно ограниченного набора утверждений. Проверка: основание найдено, относится к утверждению и поддерживает его.

**П5б.** Необоснованное положение не представляй как установленный факт. Допущение обозначь как допущение; проверяемую гипотезу — как предположение с условием проверки. Авторское толкование источника отделяй от результата самого источника. Пометку «вывод автора» ставь только в пересказе источника — чтобы отделить толкование от результата источника. Собственные решения документа не помечай. Проверка: статус положения ясен, а ссылка не выдаётся за подтверждение того, чего в источнике нет.

Определение обозначения, заголовок и инструкция не требуют доказательства как факта о системе. Смысл терминов проверяется по П7.

### П6. Разделяй общее утверждение и частный пример

Область действия наследуется из документа или раздела. При её изменении назови новую область. Частное устройство, файл или числовой пример допускается с явным ограничением его роли.

Проверка: свойство экземпляра не приписано всему классу без основания. Помеченный пример не обязан быть свойством каждого объекта класса.

### П7. Используй единые определения и обозначения

**П7а.** До использования специального смысла проверь доступность определения в документе или указанном источнике. Ранее введённое не определяй повторно. Состав определения обозначения — 4.10, первое введение — 4.13 и 3.3. Проверка: смысл доступен к рассуждению без догадки; прежнее определение использовано без копии.

**П7б.** Сопоставь короткую запись с объектами контекста 0.2. При одном подходящем объекте оставь одно название или обозначение; при двух возможных добавь полное обозначение или имя, различающее объекты. В заголовке обозначение допускается для различения предметов; факторы именуй по 6.8. Проверка: каждая запись указывает один объект без лишней пары «имя + символ».

**П7в.** Рассуждение не использует ещё не введённый смысл или недоказанное положение как установленное основание. Навигационная ссылка вперёд допустима, если от её содержания не зависит понимание текущего рассуждения. Проверка: ни один необходимый смысл или шаг не приходится восстанавливать из будущего раздела.

### П8. Укажи происхождение данных

**П8а.** Для физического, экспериментального или выбранного числового значения укажи статус: задано, измерено, взято из источника, вычислено, условно или предположено. Происхождение может быть общим для таблицы, столбца, серии или набора исходных данных. Проверка: происхождение каждого такого значения прослеживается без повторения одинаковой пометки.

**П8б.** Если из значения делается сравнительный вывод, назови характеристику сравнения, критерий и совместимые единицы. Проверка: вывод воспроизводится по данным и критерию.

Номера, индексы, идентификаторы и математические константы не требуют пометки происхождения как измеренные данные.

### П9. Примени профиль вывода

Используй один подходящий профиль из раздела 5 либо явно заданный профиль среды.

Проверка: формулы, таблицы и отступы соответствуют выбранному профилю. Проверка отображения в приложении заявляется только после фактического просмотра.

### П10. Сокращай словесное изложение

В проходе сокращения меняй только словесный текст. Формулы, обозначения, аргументы функций и последовательность математических преобразований не меняй.

**П10а. Сократи конструкцию с тем же смыслом.** Применяй тип операции, а не закрытый словарь фраз. Работай с обычным авторским текстом; цитаты, названия и программные записи не изменяй.

| Что найдено | Операция | Примеры |
| --- | --- | --- |
| Многословное условие или цель | Сократи связку, сохрани само условие или цель. | «в том случае, если» → «если»; «для того чтобы» → «чтобы». |
| Сочетание, выражающее действие | Замени глаголом того же действия, сохрани объект и условия. | «осуществляет измерение» → «измеряет»; «производится вычисление» → «вычисляется». |
| Призыв обратить внимание перед сообщаемым фактом | Удали вводный оборот, оставь факт. | «следует отметить, что корпус заземлён» → «корпус заземлён». |

Примеры допускают другие фразы этих же типов; сходства слов недостаточно. «Обеспечивает измерение» не равно «измеряет»; «необходимо измерить» — требование, оно сохраняется. Каждую замену проверь по П10в.

**П10б. Удали повтор сведений.** Найди исходное место в документе и сопоставь объект, действие или свойство, условия и значения. При совпадении оставь одно утверждение, при необходимости — ссылку; для определения проверь прежнее введение по П7а.

Проверка: удалённые сведения восстанавливаются из оставленного текста и его контекста. «Датчик измеряет перемещение штока. Перемещение штока измеряется датчиком» сокращается до первого предложения. Разные условия или значения — разные сведения.

**П10в. Проверь каждое изменённое утверждение** по исходной и новой записи:

- объект и действие или свойство;
- условия, диапазон и исключения;
- отрицание, слова «только», «все», «некоторые»;
- статус: требование, возможность, предположение или установленный результат;
- числа, единицы и точность;
- отношения: причина, следствие, последовательность событий;
- основание, источник и область применимости.

Проверка: сведения сохранены в записи или однозначно заданы контекстом. «Может» не стало «должен», «после» — «из-за», предположение — фактом. При неясности сохрани исходную запись и назови неоднозначность в отчёте.

**П10г. Проверь удаляемый фрагмент.** Раздел, абзац или пояснение можно удалить, только если сохраняются сведения П10в, определения, основания и однозначные ссылки. Цель по 1.3 не удаляй как повтор заголовка. Пояснения формулы и рисунка регулирует 1.5, повторы формул — раздел 3. Искомый результат и исходные условия нужны для самой задачи; последующее использование необязательно.

Если подходящей операции нет, оставь фрагмент без изменений. Процент сокращения не задаётся. Служебное сопоставление в технический текст не включай.

### П11. Сохрани область применимости результата

При заимствовании результата сохрани существенные ограничения источника: объекты, режимы, диапазоны и допущения. Общие условия допускается задать один раз для группы результатов. Применение за их пределами требует отдельного основания по П5.

Проверка: область утверждения не шире обоснованной области. Совпадения названия класса устройств недостаточно, если различаются существенные условия.

### П12. Проверь новое или изменённое определение

Для определения, создаваемого или изменяемого в текущей задаче, проверь обычный случай и один случай, способный выявить ошибку: нулевое значение, пустое множество, совпадение объектов или границу, если такой случай относится к области определения. Если область допускает только один случай, укажи это.

Проверка: результат однозначен и соответствует назначению определения; недопустимый случай не выдан за допустимый. Случаи проверки служебные; публикуй поясняющий пример по 2.12, а не весь протокол. Пример не заменяет обоснования. Для принятого определения источника не придумывай заново измерительную процедуру.
