# Правила оформления технических документов

Команда «оформи согласно правилам» (для документа или раздела) выполняется по разделу 0. Разделы 1–6 — сами правила, раздел 7 — итоговая проверка, раздел 8 — правила ответов в чате, раздел 9 — проверяемые правила изложения П1–П12 для документов и ответов в чате.

## 0. Порядок применения

Граница правки:

| Команда | Что меняется | Что не меняется |
| --- | --- | --- |
| «оформи согласно правилам» | форма подачи, вёрстка формул, обозначения, ссылки, таблицы, язык (разделы 1, 3–6); пропущенные шаги вывода дописываются | состав и способ вывода, результаты; существующие выводы не вырезаются; ничего нового сверх правил не добавляется |
| «проверь», «проанализируй» | ничего | отчёт и предложения |
| «перепиши», «проверь корректность и исправь» | также содержание по разделу 2, включая выбор другого способа вывода | — |

- Меняется только указанный раздел. За его пределами — только номера формул и ссылки на них, если они сдвинулись; об этом сообщается в отчёте.

Что прочитать до правки:

1. Указанный раздел целиком, от заголовка до следующего заголовка того же уровня.
2. Формулы и разделы, на которые он ссылается, и места документа, которые ссылаются на него.
3. Для каждого символа, который раздел вводит или использует, — все его вхождения в документе (поиск по LaTeX-записи), чтобы найти коллизии.

Проходы, строго по порядку; каждый проход — по своему разделу правил:

| Проход | Правила | Что проверяется |
| --- | --- | --- |
| 1. Структура | раздел 1 | заголовок называет тему; первая фраза — цель («Докажем, что …», «Получим …»), последняя — этот результат; в разделе только его тема; утверждения после доказательств; нет отступлений и повторов |
| 2. Выводы | раздел 2 | каждый переход следует из предыдущего или из формулы с номером; нет пропущенных шагов; запись условий, множеств, размеров; точное и приближённое разделены |
| 3. Обозначения | раздел 4 | система координат и точки у векторов, орты, одна буква — одна величина, название вместе с обозначением |
| 4. Формулы | раздел 3 | «где …» после каждой формулы, переносы, центрирование, аргументы функций, нумерация и ссылки |
| 5. Таблицы | раздел 5 | ячейки, заголовки |
| 6. Язык | раздел 6 | термины, референты, грамматика |
| 7. Механические проверки | раздел 7 | команды ниже; каждое найденное место разобрано: исправлено или объяснено, почему это не нарушение |
| 8. Изложение | раздел 9 | проверки П1–П12; каждое нарушение названо номером правила и исправлено |

Механические проверки (Git Bash; `F` — путь к документу). Они находят кандидатов в нарушения; решение по каждому принимается вручную. Обратная косая черта в регулярных выражениях записана как `\x5c`: инструмент агента для командной строки превращает две обратные косые черты подряд в одну, и проверки 2 и 4 в прежней записи не находили `\tag`, `\begin` и перенос `\\`.

```bash
F=docs/calibration/ROBOT_PROBE_SPHERE_CALIBRATION_THEORY_RU.md
# 1. Unicode-математика (греческие буквы, индексы, ≤, √, ·, …) вне строчных формул $…$ и вне кода
perl -CSD -ne '$m=!$m if /^\$\$\s*$/; next if $m || /^\$\$/ || /^!\[/; s/`[^`]*`//g; s/\$[^\$]*\$//g; print "$.: $_" if /[\x{3B1}-\x{3C9}\x{391}-\x{3A9}\x{304}\x{1D62}\x{2096}\x{2080}-\x{2089}\x{1D40}\x{207B}\x{2265}\x{2264}\x{2260}\x{2248}\x{B7}\x{D7}\x{221A}\x{2208}\x{2202}\x{27E8}\x{27E9}\x{2016}\x{226A}]/' "$F"
# 2. Номер формулы без ссылки ниже; ссылка на несуществующий номер
perl -CSD -ne 'push @L,$_; END{ for $i (0..$#L){ $T{$1}=$i while $L[$i]=~/\x5ctag\{([0-9.]+)\}/g } for $i (0..$#L){ next if $L[$i]=~/\x5ctag\{/; while($L[$i]=~/\((\d+(?:\.\d+)+)\)/g){ $c=$1; if(exists $T{$c}){ $later{$c}=1 if $i>$T{$c} } else { print "line ",$i+1,": ($c) has no tag\n" } } } for $t (sort keys %T){ print "($t) at line ",$T{$t}+1,": no citation below\n" unless $later{$t} } }' "$F"
# 3. Указатели без номеров формул
grep -nE 'формул[аеуыи]* (выше|ниже)|\((выше|ниже)\)|цепочк[аеуи] выше|шаг[аеу]? [0-9]+ раздела|итог[аеу]? шага|обеих сумм|последн(ее|ем) слагаем|средн(ее|ем) слагаем|равенств[а-я]* —|переход[а-я]* —|то есть|иначе говоря|Под корнем' "$F"
# 4. Перенос строки формулы без «=» в конце строки и в начале следующей (строки матриц и строки с «&» не учитываются)
perl -CSD -ne '$d+=()=/\x5cbegin\{[bpv]?matrix\}/g; $d-=()=/\x5cend\{[bpv]?matrix\}/g; if($pe && $_!~/^\s*\x5cend/ && ($pb!~/=\s*\x5c\x5c\s*$/ || $_!~/^\s*=/)){print "$.: $_"} $pe = (/\x5c\x5c\s*$/ && !/&/ && $d==0); $pb=$_' "$F"
# 5. Качественные оценки без числа
grep -nE '(^|[^А-Яа-яё])(мал(ая|ое|ые|ый|ой|ую|а|о|ы)?|допустим[а-я]*|достаточн[а-я]*|существенн[а-я]*|незначительн[а-я]*|небольш[а-я]*|примерно)([^А-Яа-яё]|$)' "$F"
```

Отчёт после правки — таблица: правило, место, что было, что стало. Ниже — нарушения, которые не исправлены, и причина (например, исправление требует изменить содержание, а команда была «оформи»).

## 1. Форма подачи

- Порядок предпочтения форм: математический вывод с обозначениями → таблица → перечень → рисунок или диаграмма → текст. Текст — только для причинных связей, которые другие формы не передают.
- Формулы не объясняются словами: вместо пересказа — подробный вывод. Запрещены пояснения шагов вида «первое равенство — …, второе — …», «последний переход — …», «вынесено за знак суммы, потому что …». Источник шага указывается только перед формулой: «Подставим (5.2.11) в …»; блок «где …» содержит только определения символов. Пересказ формулы словами («то есть корень из многочлена второй степени», «элемент на месте k равен 1, остальные 0») не пишется: формула от пересказа понятнее не становится.
- Каждое утверждение проверяется вопросом «А это объяснено?»: категории, заголовки столбцов, термины, условия вида «необходимо, но недостаточно».
- Нет качественных оценок без числа. «Мал», «случаен», «допустим», «достаточно» заменяются величиной, порогом, источником порога и примером проверки.
- Изложение идёт от простого к сложному, по одному усложнению за шаг. В шаге используются только величины этого шага.
- Нет метафор и олицетворений («невязки не видят», «оценка забрала шум», «подстраивает»): только буквальные соотношения.
- Каждый раздел начинается с цели: «Докажем, что …», «Получим соотношение для …». Конец раздела — этот результат и то, ради чего он нужен в задаче.
- Утверждение — только после доказательства: «Докажем, что …» → доказательство → результат. Выводы и «смысл» — после доказательства.
- Один вектор повествования: каждый подраздел нужен следующему. Отступления (формула Тейлора, производная по направлению и т. п.), не ведущие к главному выводу, не пишутся. Перед написанием сравниваются несколько способов изложения и выбирается самый короткий математически корректный.
- Уже написанное не повторяется: определения, формулы, пояснения.
- Заголовок раздела говорит, что в нём рассматривается или получается; общие слова без предмета («Анализ», «Модель») не годятся.
- Раздел содержит только свою тему. Величины следующих разделов в нём не появляются: в подразделе «Невязки после оценивания» нет СКО и вектора параметров x̄, если они вводятся позже.

## 2. Математические выкладки

- Вывод — цепочка равенств, по одному преобразованию на шаг: подстановка, раскрытие, сокращение показаны отдельно. Ничего не сокращается: Σ(a + b)² → Σ[a² + 2ab + b²] → Σa² + 2Σab + Σb².
- Подстановка — отдельный шаг со словами «Подставим (5.2.11) в …»: формула подставляется как есть, без преобразований на ходу (транспонирования, сокращения, перестановки, смены записи). Преобразования — следующими шагами цепочки.
- Каждый переход следует из предыдущего шага или из формулы с номером. Ссылка на «определение» допустима, только если переход действительно следует из определения.
- Производные записываются через частные производные, не через приращения Δ.
- Сначала общий вид, потом частный случай: определение (например, производная скалярной функции по вектору — строка частных производных) → вычисление элемента → подстановка.
- Доказательство начинается с той величины, о которой утверждение. Утверждение о сумме квадратов невязок начинается с суммы квадратов невязок, записанной через εᵢ, и только потом раскрывается.
- Условия записываются математически, с кванторами и множествами: ∃ ᾱ ∈ ℝⁿ \ {0̄}: J ᾱ = 0̄. Индексы задаются множеством: k, m ∈ {x, y, z}. Для каждой величины указано множество.
- Для каждого вектора указано: вектор-строка или вектор-столбец, размер.
- Явно различаются: необходимое и достаточное условие; точное равенство и приближение (≈, «в линейном приближении»); локальное и глобальное.
- Формулировки буквально корректны: «элементы 1–3 вектора x̄ — координаты центра шарика», а не «первые три элемента — центр шарика»; «условие из раздела 5.2.1», а не «условие раздела»; «нормальные уравнения» — только об уравнениях, которые ими являются.
- Названия теорем и методов — только общепринятые, проверенные по источникам. Если название не установлено, утверждение формулируется без названия.
- Поясняющий пример в упрощённых обозначениях (вектор $\bar{a}(x, y)$ вместо ${}^{B}\bar{r}_{sr}$) пишется перед итоговой формулой и начинается с того же выражения, которое поясняет.

## 3. Формулы

- Формула — отдельный блок `$$ … $$`. Все строки многострочной формулы по центру (`gathered`, не `aligned` с `&=`).
- Перенос строки — только по знаку «=», никогда внутри выражения: «=» стоит в конце строки и повторяется в начале следующей. Короткие равенства идут подряд в одной строке: a = b = c = …; перенос — когда строка становится длинной.
- После формулы — «где …»: определение каждого нового символа с единицами измерения. Оформление по ГОСТ, без маркеров списка: первое обозначение — в строке со словом «где», каждое следующее — с новой строки с отступом под первым обозначением; определения разделяются «;», последнее заканчивается точкой. В Markdown перенос — обычный перевод строки (просмотрщик пользователя переносит по нему; `<br>` даёт лишнюю пустую строку, обратная косая черта видна как символ), отступ — `&emsp;&emsp;`:

  ```
  где $G$ — матрица размером $6 \times 6$;
  &emsp;&emsp;$\bar{b}$ — вектор-столбец размером $6 \times 1$, мм.
  ```

  Каждая строка «где» начинается с обозначения; строки вида «первый множитель — …», «правая часть — …», «матрица из двух блоков имеет размер …» не пишутся. Между строками блока нет пустых строк. Пояснения, если они нужны, — отдельным абзацем после всех обозначений.
- Итог вывода (финальная формула, ради которой вывод делался, а не каждая пронумерованная) выносится в рамку `\boxed{…}` отдельным блоком сразу после последнего шага вывода: левая часть исходной величины = окончательное выражение. Если на итог ссылаются, номер `\tag` стоит у рамки, а не у цепочки. Если весь блок и есть итог без вывода, рамка ставится на сам блок.
- Указываются все аргументы функций: $\bar{p}_M(\theta)$, а не $\bar{p}_M$. Зависимые аргументы — явно: $\bar{p}_L(u, \theta(u))$.
- Векторы-строки и векторы-столбцы в формулах записываются как обычно — матрицей `bmatrix`; вектор-столбец можно записать транспонированной строкой. Если у элемента строки знак минус, соседние элементы разносятся (`\quad & \quad`), чтобы минус не читался как вычитание: $\begin{bmatrix} {}^{B}R_F \quad & \quad -I \end{bmatrix}$.
- Координаты вектора в тексте и таблицах пишутся в круглых скобках через запятую: (0, 0, 1). Числовой вектор с десятичными запятыми — через точку с запятой: (−0,048; −0,097; 127) мм.
- Нумерация по ГОСТ в пределах раздела второго уровня: первая нумеруемая формула раздела 5.3 — (5.3.1). В Markdown — `\tag{5.3.1}` внутри блока.
- Номер ставится, только если ниже в тексте на формулу есть ссылка. Указатель, стоящий до формулы, номера не оправдывает.
- Формула источника обозначается номером источника и своим номером без скобок: «L7, формула 3.2». Номер в скобках «(3.2)» — только для формул этого документа: его проверяет механическая проверка 2.
- На формулу ссылаются по номеру: «из (5.2.9)». Формула не повторяется ни отдельным блоком, ни внутри текста. Запрещены «формула выше/ниже», «шаг 4 раздела …», «подстановка обеих сумм» без номеров.

## 4. Обозначения

- Вектор — строчная буква с чертой: $\bar{r}$. Система координат — левый верхний индекс. Вектор между точками — нижние индексы от первой точки ко второй: ${}^{B}\bar{r}_{sr}$ идёт из s в r, координаты в {B}.
- Буква l для векторов не используется.
- Орт — буква e с чертой и индексом оси или вектора: $\bar{e}_x$, ${}^{B}\bar{e}_{sr} = {}^{B}\bar{r}_{sr} / \|{}^{B}\bar{r}_{sr}\|$. Буква e — только для ортов.
- Тот же вектор, нормированный или выраженный в другой системе, сохраняет букву; меняется только индекс: ${}^{B}\bar{e}_{sr}$ и ${}^{F}\bar{e}_{sr}$.
- Одна буква — одна величина во всём документе. Перед вводом символа проверяется, не занят ли он: v — скорость, k — индекс координаты, A — угол KUKA и т. д.
- Буква не должна ассоциироваться с другим смыслом: d читается как диаметр, поэтому расстояние — L.
- Матрица преобразования из системы i в систему j — ${}^{j}A_i$; называется матрицей преобразования, не калибровкой.
- Составные индексы — через точку: $p_{a.det}$.
- Названия короткие: $\hat{\bar{x}}$ — «вектор параметров, найденный МНК».
- Название и обозначение идут вместе: «через орты ${}^{B}\bar{e}_{sr}(\bar{q}_i,\bar{x})$, ${}^{F}\bar{e}_{sr}(\bar{q}_i,\bar{x})$ и вектор ${}^{B}\bar{r}_{sr}(\bar{q}_i,\bar{x})$ при касании $i$». Короткое существительное (орт, вектор, матрица) плюс обозначение внутри строки. Словами не дублируется то, что кодируют индексы обозначения (точки, система координат); контекст вроде «при касании i» сохраняется.

## 5. Таблицы

- Документы открываются в MarkText, он отображает строчные формулы `$…$` и в таблицах. Поэтому в документе любое обозначение и выражение — в ячейке таблицы, в тексте, в заголовке — пишется строчной формулой, включая одиночные греческие буквы: $\tau$, $(\tau, \psi)$, $\lvert \varepsilon_i \rvert / s > 3$, $\sqrt{52{,}19 / 31} = 1{,}30$. Unicode-индексы и Unicode-символы (εᵢ, q̄ᵢ, ≤, √, ·) вне формул не используются.
- Внутри формулы в ячейке модуль пишется `\lvert … \rvert`, не `|`: символ `|` разделяет ячейки. Десятичная запятая — `{,}`.
- Не переводятся в формулы: названия осей (ось z), ориентация KUKA в записи робота (A 180, B 0, C 180), идентификаторы (X2.0, TOOL_DATA[5]), числовые векторы из таблиц данных.
- В ответах в чате формулы в таблицах не отображаются: там ячейки — только слова, числа и Unicode-индексы.
- Каждая ячейка проверяется до отправки.
- Заголовки столбцов и категории в ячейках объяснены.

## 6. Терминология и язык

- Термины — принятые в русской инженерной и математической литературе, проверенные по источникам: МНК-оценивание (не «подгонка»), невязка (не «остаток»), идентифицируемость (не «определимость»), приращение (не «поправка»), сочленение (не «сустав»). Кальки не используются.
- Название величины говорит, чья она: «перебег шарика», а не «проезд».
- У каждого глагола есть подлежащее; у «который», «последнее слагаемое», «средняя сумма», «общий сдвиг» — явный референт.
- Проверяются грамматика, падежи, тавтологии, однокоренные повторы, столкновения терминов.

## 7. Проверка перед сдачей

1. Каждый символ, сокращение (СКО, m) и термин определены при первом использовании или раньше.
2. Ни одна буква не обозначает две величины.
3. После каждой формулы есть «где …».
4. Нет утверждений до доказательства и качественных оценок без числа.
5. У каждого номера формулы есть ссылка ниже; нет ссылок «выше/ниже» и повторов формул.
6. Обозначения и выражения в тексте и таблицах — строчными формулами $…$, без Unicode-математики.
7. Начало каждого раздела соответствует его концу.
8. Выкладки не сокращены; переносы только по «=», знак стоит на обеих строках; строки по центру.
9. Механические проверки раздела 0 выполнены, каждое найденное место разобрано.
10. За пределами указанного раздела изменены только номера формул и ссылки; ничего не добавлено сверх правил.

## 8. Ответы в чате

- Ответ — ровно на заданный вопрос. Без забегания вперёд, без дополнительных таблиц, аналогий и смежных величин.
- После правки документа — одна строка: что изменено и где. Отредактированный текст в чат не вставляется.
- Меняется только то, что попросили. «Проверь», «проанализируй» — отчёт и предложения, без правок.
- Математика в чате: внутри строки `$…$`, никогда `\(…\)`. Символ с левым верхним индексом (${}^{B}\bar{r}_{sr}$, ${}^{j}A_i$) — только в отдельном блоке `$$…$$`.
- Без блока «что дальше» с вопросом и кнопками; предложения — обычным текстом в конце.

## 9. Проверяемые правила изложения

Правила действуют для документов и для ответов в чате. У каждого правила — требование и проверка, на которую отвечают «да» или «нет». Нарушение называется номером правила. Правило о самих правилах: каждое правило определяет свои термины и имеет такую проверку.

П1. Название характеристики соответствует типу объекта.
- Требование: вектор — модуль, составляющая по оси, угол с осью; матрица — элемент, ранг, норма с указанием вида, размер; множество — число элементов; функция — значение при указанных аргументах; совокупность значений — размах, СКО или ±половина размаха; СКО, среднее, размах — только с названием величины, к которой они относятся. Характеристики разного вида без пересчёта не сравниваются.
- Проверка: для каждого слова «длина», «размер», «величина», «значение», «разброс», «СКО», «ошибка» назван объект и его тип совпадает с перечнем.

П2. Условие записано проверяемым признаком.
- Требование: условие (вводится словами «если», «при», «когда», «только если») записано равенством или неравенством определённых в тексте величин, перечнем объектов или ссылкой на условие с номером. Условие задаётся тем, чем можно управлять или что можно измерить. Оценочные слова («существенно», «заметно», «достаточно», «мало», «велико», «быстро», «верно», «корректно») — только с числовым порогом и его происхождением; слова источника — в кавычках с местом; если источник числа не даёт, это сказано.
- Проверка: для каждого условия по значениям величин из текста можно ответить «выполнено» или «не выполнено».

П3. Указательное слово имеет предмет в том же предложении.
- Требование: существительное, на которое указывают «это», «этот», «такой», «он», «она», «оно», «они», «последний», «данный», «указанный», стоит в том же предложении раньше, и между ними нет другого существительного того же рода и числа.
- Проверка: для каждого указательного слова выписан один предмет.

П4. Абзац начинается со связи с предыдущим.
- Требование: первое предложение абзаца, кроме первого в разделе, называет результат предыдущего абзаца и отношение к нему: «поэтому», «следовательно», «потому что», «чтобы проверить …», «однако». Следующий элемент перечня альтернатив — с причиной, по которой он нужен.
- Проверка: по первому предложению абзаца видны результат предыдущего абзаца и отношение к нему.

П5. У каждого утверждения есть основание.
- Требование: утверждение (свойство объекта, сообщаемое как факт) имеет основание: вывод (номер формулы или раздела), источник с местом (раздел, таблица, рисунок, страница), измерение (что, чем, где записан результат) или расчёт (формула или программа и входные данные). Утверждение с ещё не определёнными величинами или терминами не пишется — пишется «не определено; зависит от …». Без основания — пометка «предположение» и способ проверки. Толкование слов источника и причинная связь, которой в источнике нет, помечаются как вывод автора.
- Проверка: для каждого утверждения выписано основание, для каждого его термина — место определения выше.

П6. Текст для класса объектов не содержит сведений об экземпляре.
- Требование: область действия текста (класс объектов или экземпляр) названа в его начале. Текст для класса не содержит названий конкретных устройств, чисел конкретного экземпляра, имён файлов и переменных конкретной системы, элементов решения, выбранного для экземпляра. Числа из публикаций допустимы с названием устройства, условные числа — с пометкой «условно».
- Проверка: каждое имя собственное, идентификатор и число с единицей относится к любому объекту класса.

П7. Символ и термин определены до использования; название идёт с обозначением.
- Требование: при первом использовании или раньше сказано, что обозначает символ или термин, как вычисляется или измеряется, единицы, множество значений индекса. Ссылки вперёд на формулы и величины следующих разделов не допускаются. В тексте после названия величины, у которой есть обозначение, стоит обозначение («средний ход до срабатывания $\delta_{p0}$»); в заголовках обозначения не ставятся.
- Проверка: для каждого символа место определения не ниже первого вхождения; у каждой названной в тексте величины с обозначением есть обозначение рядом.

П8. У значения величины указано происхождение.
- Требование: значение величины (число, выражающее свойство объекта; не номер, индекс, идентификатор) помечено одним из видов: задано, измерено (где записано), источник (место), вычислено (формула или программа, входные данные), условно, предположение. Вывод по значению называет величину, с которой его сравнивают.
- Проверка: у каждого значения величины есть пометка происхождения.

П9. Оформление соответствует средству просмотра.
- Требование: в чате символы с левым верхним индексом и длинные выражения — только в `$$…$$`, в таблицах нет LaTeX, нет `&emsp;`; в `.md` для MarkText LaTeX допускается в таблицах.
- Проверка: для вида вывода пройден его перечень.

П10. Каждый элемент текста нужен.
- Требование: элемент (раздел, абзац, таблица, строка, формула, рисунок, перечень) использует другой элемент, ведущий к цели документа, и ни один существующий элемент не выполняет ту же функцию. Проверка выполняется при написании; её результат — оставить или удалить элемент, в документ он не записывается.
- Проверка: для каждого элемента назван использующий его элемент; две одинаковые функции не найдены.

П11. Результат источника переносится только на класс объектов, на котором он получен.
- Требование: рядом с результатом источника назван класс объектов, на котором он получен; применение к другому классу — только с основанием по П5.
- Проверка: класс назван и совпадает с областью действия утверждения, где результат используется.

П12. Определение проверено на конкретных случаях.
- Требование: определение применено хотя бы к двум случаям из области действия, включая крайний; если для случая оно даёт неверный результат или не даёт никакого, оно исправляется. Определение источника, не задающее величину или способ проверки, как определение не переносится.
- Проверка: для каждого определения выписаны случаи и результат для каждого.
