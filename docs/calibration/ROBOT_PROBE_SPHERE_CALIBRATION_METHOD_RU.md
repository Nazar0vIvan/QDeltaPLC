# Калибровка центра шарика WP-500 по эталонной сфере: установка и метод

## 1. Назначение документа и состояние

Документ проецирует теорию из `docs/calibration/ROBOT_PROBE_SPHERE_CALIBRATION_THEORY_RU.md` (далее «теория») на установку проекта: робот KUKA KR 10 R1420 с контроллером KR C4, щуп WP-500, эталонная сфера Ø25 мм, ПЛК Delta, интерфейс RSI. Обозначения, термины и номера формул — из теории; новые введены там, где используются. Анализ литературы — `docs/calibration/ROBOT_PROBE_SPHERE_CALIBRATION_LITERATURE_RU.md` (далее «анализ литературы»); математика для ММК — `docs/calibration/ROBOT_PROBE_SPHERE_CALIBRATION_MODELS_RU.md` (далее «модели»), номера её формул начинаются с буквы m.

Задача: найти положение центра рубинового шарика WP-500 относительно фланца робота, чтобы затем измерять поверхности деталей этим щупом. Сейчас известно только приближение TOOL_DATA[5]: X −0,048, Y −0,097, Z 127 мм.

Состояние: метод калибровки не выбран. По порядку анализа (теория, раздел 1) КТК определён (теория, раздел 4); факторы классифицированы по способу количественного определения на установке, форме количественного представления, возможности нейтрализации и условию применимости значения (раздел 5 этого документа, теория, раздел 5); выбор возможен после того, как факторы, у которых есть способ, количественно определены. Сейчас документ содержит: данные установки (разделы 2–4), факторы влияния с их классификацией и значениями, известными без измерений на установке (раздел 5).

Центр шарика TOOL_DATA[5] измерен на КИМ для щупа с адаптером вне робота в системе адаптера {AD}; принято, что после установки {AD} совпадает с {F} (`docs/context/ARCHITECTURE.md`, Controller tool data). ### 2.2. Системы координат на контроллере

- {B} совпадает с WORLD KUKA: программа задаёт `$BASE = $NULLFRAME`, `$ROBROOT` в машинных данных нулевой.
- {F} — система FLANGE KUKA; в проекте — последнее преобразование `Kr10Kinematics::solveFK`.
- {P} — TOOL_DATA[5] с $A = B = C = 0$.

KUKA задаёт позу координатами X, Y, Z, мм, и углами Эйлера Z-Y-X $A$, $B$, $C$, градусы. Поворот фланца:

$$
{}^{B}R_F(A, B, C) = R_z(A)\,R_y(B)\,R_x(C)
\tag{2.2.1}
$$

где $A$, $B$, $C$ — углы позы KUKA, градусы; буква $A$ без индексов — угол, а не матрица преобразования;
&emsp;&emsp;$R_z(A)$, $R_y(B)$, $R_x(C)$ — матрицы поворота на углы $A$, $B$, $C$ вокруг осей z, y, x.

По (2.2.1) ориентация A 180, B 0, C 180 направляет ось z фланца, то есть стилус, вертикально вниз.

## 3. Регистрация касания на установке

### 3.1. Путь сигнала и задержка

Путь сигнала срабатывания: выход WP-500 → вход X2.0 ПЛК Delta → программа ПЛК копирует его на выход Y1.7 → вход 8 модуля EL1809 → `$IN[8]` (`docs/context/ARCHITECTURE.md`, Additional hardware and Delta I/O wiring; с 2026-11-06, до этого — выход Y1.5, вход 11, `$IN[11]`). Объект STOP контекста RSI останавливает движение по переднему фронту `$IN[8]` на контроллере, без участия ПК; тестом `RSI_Probe_Lin` (`resources/files/rsi/RSI_Probe_Lin_CONTRACT.md`) остановка проверена только при прежнем подключении к `$IN[11]`.

### 3.2. Углы сочленений в момент обнаружения касания

Для уравнений касания (модели, раздел 2.1) нужны фактические углы сочленений в цикле, в котором контроллер увидел `$IN[8]`.

| <nobr>Источник</nobr> <nobr>углов</nobr>          | <nobr>Что</nobr> <nobr>это</nobr>                                                                                                           | <nobr>Пригодность</nobr>                                                                                                                                                                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AIPos` в обмене RSI    | «Axis-specific actual position of robot axes A1 to A6» (руководство RSI 3.3) — фактические углы, каждый цикл 4 мс | по смыслу пригодны; при текущей настройке ETHERNET1 (`Precision` 1) передаются с шагом 0,1° — измерено по записи `records/rsi_packets_test_lin_20261030_110905_072.csv` (каталог сборки): `A2="-89.5"`, `A3="89.5"`; в таком виде непригодны |
| `$POS_ACT`, `$AXIS_ACT` | заданные (setpoint) положения (руководство System Variables 8.1–8.3, разделы 3.134, 3.28)                         | непригодны: не фактические                                                                                                                                                                                                                   |
| `$AXIS_ACT_MEAS`        | фактические углы привода (там же, 3.29)                                                                           | после остановки; тормозной путь после обнаружения входит в результат                                                                                                                                                                         |
| `$AXIS_INT`, `$POS_INT` | положение в момент прерывания (там же, 3.32, 3.138)                                                               | момент выборки и фактическое или заданное — не указано                                                                                                                                                                                       |

Квантование 0,1° по A1 при расстоянии около 1105 мм от оси A1 до шарика даёт ошибку до $0{,}05° \cdot 1105 \cdot \pi/180 = 0{,}96$ мм и СКО $0{,}1°/\sqrt{12} \cdot 1105 \cdot \pi/180 = 0{,}56$ мм на касание. Шаг $10^{-4}$° даёт СКО 0,56 мкм на сочленение A1, шаг $10^{-3}$° — 5,6 мкм. Действует ли параметр `Precision` на число знаков передаваемых значений, руководство RSI 3.3 не описывает.

Для калибровки и для последующих измерений нужно одно и то же вычисление позы по углам — `Kr10Kinematics::solveFK`. Использует ли контроллер модель «positionally accurate robot» (KSS 8.3, раздел 5.6), не проверено: в `$custom.dat` указано `$DEACTIVATE_ABS_ACCUR=FALSE`; декартовы позы контроллера с позами `solveFK` смешивать нельзя.

## 4. Известные данные

### 4.1. Ручное грубое измерение центра сферы

1. Настройки: режим T1, инструмент TOOL_DATA[5], база World, ручное перемещение в координатах World.
2. Десять касаний, по пять при двух ориентациях TCP; в обеих стилус направлен вертикально вниз: A 180, B 0, C 180 и A 0, B 0, C 180 (поворот на 180° вокруг оси стилуса).
3. В каждой ориентации: одно касание сверху (перемещение по −Z), затем четыре горизонтальных касания примерно на высоте экватора сферы со сторон +X, −X, +Y и −Y.
4. Робот перемещается с наименьшим инкрементом, пока не загорится светодиод щупа. Со smartPAD записывается поза TCP: X, Y, Z, A, B, C, S, T.
5. Центр сферы — аппроксимация сферы по десяти записанным положениям.

Файлы: `resources/calibration_sphere_jog_points.txt` (позы в виде `E6POS`), `resources/json/calibration_sphere.json` (те же позы в массиве `roughPoints`, диаметр сферы, объект `table`), `resources/cad/CALIBRATION_STAND.stp` (модель стойки в {S}).

## 5. Факторы влияния на установке

Факторы — ФВ1–ФВ23 по разделу 3.2 анализа литературы; признаки классификации — по разделу 5 теории: способ количественного определения, форма количественного представления, возможность нейтрализации, условие применимости значения. Средства установки — разделы 2 и 3; лазерного трекера, датчика силы и термометров в составе установки нет. Числа источников для других роботов и щупов (анализ литературы, раздел 3.7.2) на установку не переносятся.

Линейное приближение (теория, раздел 5) на установке применимо: смещение $(\sigma_{t1}^2 + \sigma_{t2}^2)/(2L)$ при СКО шума 0,04 мм по каждой оси (паспортная повторяемость робота, принятая за СКО с запасом; раздел 2.1) и $L = 14$ мм равно $0{,}04^2/14 = 1{,}1 \cdot 10^{-4}$ мм (вычислено). При шаге `AIPos` 0,1° СКО от квантования A1 — 0,56 мм на касание (раздел 3.2); если вся эта составляющая перпендикулярна вектору из центра сферы в центр шарика, смещение равно $0{,}56^2/(2 \cdot 14) = 0{,}011$ мм (вычислено); такой шаг непригоден (раздел 3.2).

## 6. Метод калибровки

Метод калибровки не выбран. Его выбирают на шаге 7 (теория, раздел 1): из методов, для которых рассчитан $\chi_{95}$, — метод с наименьшим $\chi_{95}$ (теория, раздел 4.3). Для выбора нужны:

1. Перечень факторов, отобранных на шаге 4.
2. ММК для отобранных факторов (шаг 5).
3. Условия нейтрализации из раздела 5, которые выполняет метод.
4. Количественные характеристики отобранных факторов, у которых есть способ количественного определения и которые метод по пункту 3 не нейтрализует (шаг 6). Вид характеристики — по форме количественного представления из раздела 5: значение, оценка значения, распределение или верхняя оценка разброса. ФВ7, повторяемость щупа (ФВ9, ход до срабатывания) и случайная часть задержки сигнала (ФВ15) определяются только в сумме, поэтому получают одну характеристику — шум касания.

Отобранные факторы без способа количественного определения в ММК не входят (теория, раздел 5). Если у такого фактора есть условие нейтрализации, метод обязан его выполнять; если нет, вклад фактора виден только в измеренном $\chi_{95}$ и при перекрёстной проверке (модели, раздел 4.5).
